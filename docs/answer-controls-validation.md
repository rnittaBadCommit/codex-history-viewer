# 質問・回答の開閉操作：実装と検証

## 実装

- `media/chatView.js`: 本文から user / assistant の `messageIndex` を特定。中ボタンの `mousedown` をキャンセルして即時開閉し、`auxclick` では再度開閉しない。折りたたみ中のみダブルクリックを処理する。
- 自動折りたたみ用の既存 `expandedMessageIndexes` と、手動の `manuallyCollapsedMessageIndexes` を分けた。`off`、短い回答、詳細表示中でも手動操作できる。検索やメッセージ移動による明示的な展開を優先する。
- 左クリックによる回答選択とフォーカスを追加。既存のブックマーク・ナビゲーション用選択は維持する。セッション切り替えや新規表示で回答選択を解除する。
- 右クリックは `data-vscode-context` と `webview/context` を利用。本文だけに所属セッション、モデル更新リビジョン、回答番号を付与し、古いメニュー操作や別セッションへの操作を拒否する。標準コピー項目は非表示にしない。
- `src/chat/chatPanelManager.ts` と `src/extension.ts`: アクティブで準備済みのパネルにコマンドを配送。Webview 内の回答フォーカスを VS Code のコンテキストキーに反映する。
- ショートカットは VS Code が Webview から転送されたキーを処理する経路に統一。`Ctrl+Space` の独自ハンドラーは追加しないため、標準キーボード設定で変更でき、二重トグルも発生しない。入力・IME・連続キーイベントは Webview 側でも抑止する。
- 折りたたみ前に回答先頭の表示位置を取得し、再描画後に同じ回答へ即時スクロールする。先頭が画面外ならプレビューを画面内へ戻し、展開時も先頭付近の位置を維持。既存のスクロール位置保存を更新する。
- 新しい固定ボタンや外部ライブラリは追加していない。回答本文のリンク・操作ボタン上の中クリックは既存操作を優先する。

## 自動検証

`scripts/tests/answer-expansion.test.cjs` は本番ソースの関数とホスト側メソッドを TypeScript AST から読み込み、DOM・レイアウト・Webview ホスト境界を模した fixture で実行する。ブラウザーや VS Code の実機テストとは異なる。

21 件が成功した。主な対象は以下。

- 質問文に対する中クリック・ダブルクリック・ショートカット・メニューの双方向開閉。
- 先頭／中央／末尾を想定した見出し・表セル・コード要素、中ボタンキャンセル、`auxclick` による二重開閉の防止。
- ツール／メッセージ外 UI の除外、入れ子 SVG・テキストノード、リンク・ボタンの除外。
- 左クリック選択、コマンドによる双方向開閉、入力欄・IME・キーリピート・フォーカス喪失・inert 領域の除外。
- 折りたたみ中だけのダブルクリック展開。
- ネイティブメニュー用コンテキスト、コピー項目維持、古いリビジョン・別セッション・不正回答番号の拒否。
- `off` / `auto` / `always`、短い回答、詳細表示、検索などによる明示的な展開との互換性。
- 深くスクロールした回答のプレビュー表示、展開時の先頭位置維持、既に見えているプレビュー位置の維持。
- セッション状態リセット、1,500 回答での対象特定、ローカライズとキー割り当て、アクティブパネルへの配送。

依存関係インストール後に `npm test` で実行する。この環境では Node テストランナーの通常の隔離実行が失敗したため、テスト用スクリプトは `--test-isolation=none` を指定する。各 fixture の VM コンテキストは個別に作成する。実行コマンドは次のとおり。

```sh
node --test --test-isolation=none scripts/tests/answer-expansion.test.cjs
```

TypeScript 6.0.3 のコンパイラー API、Node 20 型定義、VS Code 1.90.0 型定義で全ソースを型チェックし、エラー 0 件を確認した。変更した JavaScript と全 Webview スクリプトの構文チェックも成功した。

## ビルド環境の制約

作業開始時のディレクトリにはソースがなかったため、接続済み GitHub API から上流のスナップショットを取得し、作業用の `codex-history-viewer/` リポジトリを作成した。履歴ファイルや既存のインストール先は変更していない。

- `npm ci --offline --ignore-scripts`: キャッシュにない依存パッケージがあり失敗。直接の GitHub / npm 通信はネットワーク制限で利用できない。
- `npm run lint` / `npm run typecheck` / `npm run compile` / `npm run package`: リポジトリ指定 Node 24.22.1 / ICU 78.3 に対し、環境が Node 24.15.0 / ICU 78.2 のため、ローカライズ生成のバージョンチェックで停止する。標準パイプライン成功とは扱わない。
- ローカライズ生成は一時コピーでバージョン検査だけを外して実行した。リポジトリの生成スクリプトと要求バージョンは変更していない。ローカライズ内容・キー検査を実行済み。正式ビルド時には指定 Node で再生成する。
- TypeScript は環境にあった同一バージョン 6.0.3 を利用した。型定義は GitHub から取得し、ローカルの未追跡 `node_modules` に置いた。
- VSIX は全 TypeScript をコンパイルし、既にインストールされていた同じ 2.20.0 の変更対象外レンダラーバンドル・Zstd バンドル・Markdown ランタイムを再利用して ZIP 形式で生成した。VSIX 内の manifest、実行コード、リソース整合性を検査した。さらに VS Code CLI で `/tmp` 内の独立したプロファイルへインストールし、拡張機能一覧に表示されることを確認した。通常の `vsce package` による再ビルドや実際の画面操作の試験とは区別する。
- Linux のヘッドレスブラウザー起動も socket / shutdown のサンドボックス制限で失敗した。Windows 上の自動スクロール、VS Code 本体でのメニュー表示・キー配送は実機未検証。

10. 長大な回答・長大なセッション、Markdown 表、コード、画像、遅延レンダリングされる図を含む回答で表示位置の安定性を確認する。
